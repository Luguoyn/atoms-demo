# Atoms Demo 常见问题（FAQ）

> 面向使用者与评测者。技术细节见 [PRODUCT.md](./PRODUCT.md)，接口见 [API.md](./API.md)，部署见 [DEPLOY.md](./DEPLOY.md)。

### 1. 没有 API Key 能用吗？

能，而且**完整可用**。服务端未配置 key（或设置 `MOCK_LLM=1`）时会自动进入 **mock 演示模式**：内置确定性 Agent 会产出完整事件流（计划、流式写入、校验、完成），并生成一个真实可交互的示例应用（如待办清单）。界面会标注「演示模式」。有 key 时才是真实模型生成。

### 2. 我的数据存在哪里？会上传到服务器吗？

项目、消息、版本、设置全部保存在**你浏览器本地的 IndexedDB**，服务端无存储、无账号体系。唯一会发送到服务端的是：你输入的 prompt、当前应用源码（迭代时需要）、以及 BYOK 的 key（仅本次请求转发，不落盘、不写日志）。换浏览器/清缓存后数据不会自动同步。

### 3. 生成失败了 / 一直转圈怎么办？

- 先看错误提示：鉴权失败 → 检查 key；模型限流 → 稍后重试；超时 → 简化需求或换更快的档位。
- 点错误消息上的「重试」，或用「重新生成 / 编辑重发」调整需求。
- 生成过程中可以随时点「停止」（或 `Esc` / `mod+.`）；已写出的文件会保留为「部分完成」。
- 如果服务端是公开演示，可能是**演示额度用尽**（默认 12 次/小时/IP）——在设置里填自己的 API Key（BYOK）即可继续，或等重置时间。

### 4. 为什么生成的是静态应用，不能做后端/数据库吗？

这是本 Demo 的**刻意边界**：生成物是自包含静态应用（`index.html` + `styles.css` + `app.js`），无外部依赖、可离线运行、可导出带走、可在 iframe 沙箱安全预览。后端/数据库/多文件工程需要沙箱构建与托管能力，属于路线图中的扩展方向（见 PRODUCT.md §13），本轮不做。复杂需求会被简化为前端实现。

### 5. 怎么换成自己的模型？

有两种方式：

1. **服务端配置**（部署者）：在环境变量里设置 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`，支持任意 OpenAI 兼容接口
   - DeepSeek 直连：`https://api.deepseek.com` + `deepseek-chat`
   - OpenCode Go：`https://opencode.ai/inference/go/openai/v1` + `deepseek-v4.1-flash`（默认验证配置）
2. **BYOK**（使用者）：在页面右上角「模型设置」里填 Base URL / 模型 / API Key。key 只存在浏览器本地，且不消耗服务端演示额度。

### 6. 演示额度用完了怎么办？

服务端密钥模式下，每个 IP 默认每小时 12 次生成（并发上限 2）。额度用尽时：
- 等待重置（设置弹窗会显示剩余额度与重置时间）；
- 或在「模型设置」里填自己的 API Key（BYOK）——**BYOK 不计入演示配额**；
- 或本地部署一份，用自己的 key。

### 7. 怎么部署到线上？

首选 **Vercel**：GitHub 导入仓库 → 设置 `LLM_*` 环境变量 → Deploy，几分钟得到 HTTPS 链接。也支持 Netlify / Render / Docker 自托管。逐步说明与常见坑见 [DEPLOY.md](./DEPLOY.md)。不想部署也可以本地 `npm run dev` 后用 `scripts/tunnel.ps1` 起临时公网链接（cloudflared quick tunnel，无需账号）。

### 8. 怎么把应用分享给别人？

三种方式：
- **分享链接**：预览工具栏「分享」→ 应用文件压缩编码进 URL（`#share=...`），对方打开即导入为项目（无需后端存储）。应用很大时链接会很长，超过限制会提示改用导出。
- **导出**：单文件 HTML（双击即用）或 ZIP（含源码），发给对方。
- **项目 JSON**：导出整个项目（含消息与版本历史），对方通过「导入项目」恢复。

### 9. 支持哪些模型 / 接口？

任何 **OpenAI 兼容的 chat-completions** 接口都可以：DeepSeek 官方、OpenCode Go 网关、OpenAI、以及各类兼容网关（可配 `LLM_EXTRA_HEADERS` / `LLM_USER_AGENT`）。模型需要支持 **function calling** 与**流式输出**才能获得最佳效果（Agent 用工具写文件）；不支持流式的网关会走整包解析降级。reasoning 模型可通过 `LLM_REASONING_EFFORT` 或请求参数 `reasoningEffort` 调节预算。

### 10. 什么是 prompt cache？对成本有什么影响？

多轮生成时，每一轮都要把「系统提示 + 当前文件 + 历史」重新发给模型。如果网关支持 **prompt 前缀缓存**（OpenCode Go 通过 `x-opencode-session` 做路由/会话粘性），相同前缀的输入 token 会命中缓存，价格远低于普通输入 token，首字延迟也会降低。命中前提：**相同前缀足够长 + 稳定的 session 头**；缓存传播有延迟，跨 session 在缓存预热后也可能命中（实测 0% 与 98% 都出现过，不要假设跨 session 必然不命中）。本项目对 `opencode.ai` 端点自动发送稳定的 session 头，并提供 `scripts/cache-probe.mjs` 实测脚本：本机实测同一 session 第二轮 **98% 的 prompt tokens 命中缓存**（3,968 / 4,034），命中时时延约降 20%–45%（不同次运行有波动）。即使没有缓存，功能也不受影响，只是成本略高。完整数据见 [PRODUCT.md §8.4](./PRODUCT.md#84-prompt-cache-实测opencode-go--deepseek-v41-flash)。

### 11. 生成的应用能带走吗？能继续开发吗？

可以。预览工具栏「导出」支持**单文件 HTML**（内联样式与脚本，双击即可运行）与 **ZIP**（原始三文件 + README）。生成物没有外部依赖，你可以把它放进任何静态托管，或用编辑器继续改。

### 12. 为什么我在预览里添加的数据，刷新后不见了？

预览 iframe 运行在 `sandbox` 沙箱中（不放行 `allow-same-origin`），隔离了生成物与宿主页面，因此**预览内**的 `localStorage` 会被替换为内存垫片，刷新预览后应用内数据不保留。项目、消息、版本这些**平台数据**会持久化。想要真实持久化，请用预览工具栏「在新窗口打开」或导出的 HTML 文件运行。

### 13. 生成过程能看到"AI 在想什么"吗？用量在哪看？

可以看到阶段与步骤：左侧消息流展示计划卡（应用名/功能/文件）、工具调用步骤（写入哪个文件、成功/失败）、校验结果；右侧预览区显示当前阶段。生成结束的 `usage` 会展示在预览区与消息操作里（输入 / 缓存命中 / 输出 tokens）。更细的运行时日志在「控制台」tab。

### 14. 这个项目是 Atoms 官方产品吗？

不是。这是一个**独立的复刻 Demo**，用于笔试/作品展示，与 Atoms 官方无隶属关系；差异对照见 [PRODUCT.md §1.4](./PRODUCT.md#14-与-atoms-的关系与差异)。
